Deux exemples d'environnement

Tout ce qui suit est illustré sur deux machines concrètes, prises comme références : une sous Windows, une sous Linux. Votre configuration sera probablement très proche de l'une des deux ; adaptez seulement les chemins.

Sous Windows

Système
Windows 11, 64 bits
Interpréteur Python
Python 3.13, installé dans C:\Users\vous\AppData\Local\Programs\Python\Python313
Pilote de capture
Npcap 1.79, installé avec l'option « WinPcap compatibility mode »
Dossier du projet
C:\analyseur
Environnement Python isolé
C:\analyseur\.venv — créé à l'étape 4, il contient les bibliothèques du projet sans toucher au reste du système
Compte sur ce site
vous@example.com — créé avant l'installation, c'est lui qui recevra les captures
Droits
Console lancée en administrateur : sans cela, le pilote refuse de s'ouvrir
Réseau observé
Une connexion Wi-Fi, adresse locale 192.168.1.15

Sous Linux

Système
Ubuntu 24.04, 64 bits
Interpréteur Python
Python 3.12, fourni par la distribution — /usr/bin/python3
Bibliothèque de capture
libpcap, presque toujours déjà présente ; au besoin libpcap0.8
Dossier du projet
/home/vous/analyseur
Environnement Python isolé
/home/vous/analyseur/.venv — créé à l'étape 4
Compte sur ce site
vous@example.com — le même compte que sous Windows, il n'y en a qu'un
Droits
Les droits root, ou la capacité cap_net_raw sur l'interpréteur. Sous Linux il n'y a pas de « console administrateur » à ouvrir, mais lire les paquets reste un privilège
Réseau observé
Une interface Wi-Fi ou Ethernet — wlan0, eth0 — adresse locale 192.168.1.15

Rien de tout cela n'est propre à une machine : ce sont simplement les éléments dont vous aurez besoin de connaître la valeur au moment de lancer l'application. Le fichier de configuration .env est identique sur les deux systèmes.

Le mode d'emploi, étape par étape

  1. Récupérez le projet depuis https://github.com/tad-code/packet-analyzer. Soit en cliquant sur Code puis Download ZIP et en décompressant dans C:\analyseur, soit par clonage si vous avez Git : git clone https://github.com/tad-code/packet-analyzer C:\analyseur. Vous devez obtenir un dossier contenant notamment app.py, requirements.txt, verifier_prerequis.py, .env.example, demarrer-analyseur.bat pour Windows et demarrer-analyseur.sh pour Linux.
  2. Installez Python 3. Sous Windows — depuis python.org, en cochant « Add Python to PATH » pendant l'installation. Vérifiez dans une console : python --version, qui doit afficher Python 3.13.x. Si la commande n'est pas reconnue, Python n'est pas dans le PATH : réinstallez en cochant la case.
    Sous Linux — Python est déjà présent, mais l'outil de création d'environnements ne l'est pas toujours : sudo apt install python3 python3-venv (Debian, Ubuntu, Kali) ou sudo dnf install python3 (Fedora, RHEL). Vérifiez avec python3 --version, qui doit afficher Python 3.10 ou plus récent.
  3. Assurez-vous que la capture est autorisée. C'est l'étape qui échoue le plus souvent, et elle ne se ressemble pas du tout d'un système à l'autre. Sous Windows — installez le pilote Npcap depuis npcap.com, et sur la dernière page de l'installateur, laissez cochée l'option « Install Npcap in WinPcap API-compatible Mode ». Ouvrez ensuite la console en administrateur. C'est ce pilote qui permet de lire les paquets : sans lui, l'application démarre mais ne voit aucune carte réseau. Le script verifier_prerequis.py vous le dira en une ligne.
    Sous Linux — le pilote s'appelle libpcap et il est presque toujours déjà installé ; en cas de doute, sudo apt install libpcap0.8. Il n'y a pas de pilote à poser, en revanche lire les paquets exige des privilèges. Le plus simple est de lancer l'application avec sudo.
    La méthode plus fine consiste à donner la seule capacité nécessaire à l'interpréteur, plutôt que de tout exécuter en root : sudo setcap cap_net_raw,cap_net_admin=eip "$(readlink -f .venv/bin/python)". À savoir avant de la lancer : si .venv/bin/python n'est qu'un lien vers le Python du système, cette commande accorde la capacité au Python du système, donc à tous ses usages et pas seulement à ce projet. C'est pour cette raison que sudo reste le choix le plus sûr sur un poste personnel.
  4. Créez l'environnement Python et installez les dépendances, dans une console qui a les droits décrits à l'étape précédente. Sous Windows — cd C:\analyseur, puis python -m venv .venv et .venv\Scripts\python.exe -m pip install -r requirements.txt.
    Sous Linux — cd ~/analyseur, puis python3 -m venv .venv et .venv/bin/python -m pip install -r requirements.txt.
    La première commande isole les bibliothèques, la seconde les installe. Comptez une ou deux minutes : plusieurs paquets sont téléchargés, dont Scapy, la bibliothèque qui lit les paquets.
  5. Déclarez votre compte et votre configuration. Copiez .env.example en .env, puis ouvrez ce fichier avec un éditeur de texte. Il contient, avec des valeurs d'exemple : 
    SUPABASE_URL=https://votre-projet.supabase.co
SUPABASE_ANON_KEY=sb_publishable_votre_cle_publique

FLASK_SECRET_KEY=une-longue-chaine-aleatoire-a-vous
SESSION_COOKIE_SECURE=0

ANALYSEUR_COMPTE_COURRIEL=vous@example.com
ANALYSEUR_COMPTE_MOT_DE_PASSE=votre-mot-de-passe

HOST=127.0.0.1
    Les deux lignes ANALYSEUR_COMPTE_* sont celles qui comptent : elles désignent le compte auquel vos captures seront rattachées. Utilisez le compte que vous avez créé sur ce site. HOST=127.0.0.1 limite l'écoute à votre machine ; HOST=0.0.0.0 l'ouvre à votre réseau local, pour l'ouvrir depuis un téléphone. Ce fichier n'est jamais publié : il reste sur votre disque.
  6. Lancez l'application. Sous Windows — double-cliquez sur demarrer-analyseur.bat, ou lancez .venv\Scripts\python.exe app.py.
    Sous Linux — rendez le script exécutable une fois pour toutes avec chmod +x demarrer-analyseur.sh, puis lancez ./demarrer-analyseur.sh — ou directement .venv/bin/python app.py. Le script rappelle, avant de démarrer, si les privilèges de capture manquent.
    Dans les deux cas, une console s'ouvre et affiche : 
      Analyseur reseau
  mode : local (capture active)
  adresse locale : http://127.0.0.1:5000
  depuis un telephone du reseau : http://192.168.1.15:5000
  comptes : Supabase Auth
  capture attribuee au compte : vous@example.com
    Trois vérifications immédiates : mode : local indique que la capture est active ; la ligne capture attribuee au compte confirme que votre compte est bien lu depuis .env ; et l'adresse affichée est celle à ouvrir. Gardez cette console ouverte : la fermer arrête l'application.
  7. Ouvrez http://127.0.0.1:5000 dans le navigateur de cette machine, puis allez sur la page Capture. Choisissez la carte réseau à écouter dans la liste — sur l'exemple, l'interface Wi-Fi — et cliquez sur Démarrer.
  8. Faites circuler du trafic. Une capture ne montre que ce qui passe : ouvrez une page web, lancez une mise à jour, envoyez un message. Les premières lignes apparaissent en quelques secondes, avec l'heure, les adresses source et destination, le protocole et le port de service.
  9. Enregistrez la capture en cliquant sur Enregistrer cette capture. Elle rejoint votre historique, ici même sur le site, et devient consultable depuis n'importe quel appareil, y compris votre téléphone. Seules les communications sont conservées : une capture produit des milliers de paquets, dont l'analyse individuelle n'aurait pas de sens.

Vérifier que tout est en place

Le projet fournit deux vérifications, à lancer dans le dossier, console en administrateur.

verifier_prerequis.py — contrôle Python, les dépendances et le pilote de capture. Vous devez voir, en particulier : 

Pilote de capture : PRESENT

Si vous lisez ABSENT à cette ligne, Npcap n'est pas installé, ou la console n'est pas en administrateur. Aucune capture n'est possible avant d'avoir réglé ce point.
Ce script est réservé à Windows : il inspecte les pilotes et les dossiers d'installation propres à ce système. Sous Linux il n'existe pas d'équivalent, parce qu'il n'y a rien à installer — libpcap est fourni par la distribution. Le contrôle se fait autrement : si les privilèges manquent, l'application le dit elle-même au démarrage et la page Capture explique ce qui bloque.

La suite de tests, qui couvre la lecture des paquets, le cloisonnement entre comptes et l'explication des communications. Sous Windows : .venv\Scripts\python.exe -m pytest tests/ -q. Sous Linux : .venv/bin/python -m pytest tests/ -q. Le résultat attendu se termine par une ligne de cette forme : 

149 passed in 0.79s

Le nombre augmente à chaque version : ce qui compte est qu'aucune ligne n'indique « failed ». Ces tests ne touchent à aucun réseau et n'envoient rien : ils vérifient le comportement du code sur des paquets simulés.

Ce qui bloque le plus souvent

« Aucune interface réseau n'a été détectée »

Sous Windows : le pilote Npcap est absent, ou l'application n'a pas les droits administrateur. Réinstallez Npcap en cochant le mode compatible WinPcap, puis relancez la console en administrateur. C'est la cause la plus fréquente, et le contrôle verifier_prerequis.py la désigne en une ligne.
Sous Linux : les privilèges de capture manquent. Relancez avec sudo ./demarrer-analyseur.sh, ou accordez la capacité cap_net_raw comme expliqué à l'étape 3. Vérifiez aussi que l'interface demandée existe bien, avec ip link.

La capture démarre mais aucun paquet n'apparaît

Deux explications : la mauvaise carte réseau est écoutée — sur une machine qui a le Wi-Fi et une carte virtuelle, choisissez celle qui correspond à votre connexion réelle — ou bien aucun trafic ne passe. Ouvrez une page web pendant la capture : les paquets doivent apparaître aussitôt.

Mon téléphone ou un autre appareil n'atteint pas l'adresse

127.0.0.1 ne fonctionne que sur la machine qui exécute l'application : sur tout autre appareil, il désigne cet appareil-là, où rien n'écoute. Depuis un téléphone du même Wi-Fi, utilisez l'adresse réseau affichée au lancement, du type http://192.168.1.15:5000 — et mettez HOST=0.0.0.0 dans .env — ce que font déjà les deux scripts de démarrage.

L'adresse réseau ne répond pas depuis un autre appareil

Sous Windows : le réseau est probablement classé « public », et un antivirus doté d'un pare-feu refuse alors les connexions entrantes — y compris lorsque le pare-feu de Windows est désactivé. Classer le réseau en privé suffit généralement : Set-NetConnectionProfile -InterfaceAlias 'Wi-Fi' -NetworkCategory Private. Sur un Wi-Fi public (café, hôtel), refaites l'inverse.
Sous Linux : vérifiez d'abord le pare-feu local, souvent ufw — sudo ufw allow 5000/tcp s'il est actif. Les distributions n'ont pas d'équivalent au classement « public / privé » de Windows.
Dans les deux cas : si la box isole ses appareils entre eux, aucun réglage de l'ordinateur n'y remédiera, et le câble USB reste la solution.

Un appareil du réseau demande un identifiant

C'est le comportement normal, pas un défaut. Seule la machine qui exécute l'application est reconnue automatiquement ; tout ce qui arrive par le réseau doit s'authentifier, et ne voit alors que les captures du compte utilisé.

Le site en ligne semble afficher une ancienne version

L'adresse publique n'est pas mise à jour automatiquement à chaque déploiement : elle doit être reportée sur la dernière version. Le script deployer-en-ligne.bat fait les deux en une seule commande et vérifie ensuite que l'adresse répond.

Ce qui ne quitte pas votre machine

L'application lit les paquets localement, sur votre machine. Le fichier .env, qui contient vos identifiants, reste sur votre disque et n'est jamais publié. Ce qui remonte sur ce site se limite aux communications que vous avez explicitement enregistrées, rattachées à votre compte — et visibles de vous seul.

Capturez uniquement sur un réseau que vous êtes autorisé à observer : le vôtre, ou celui pour lequel vous disposez d'un accord écrit.
